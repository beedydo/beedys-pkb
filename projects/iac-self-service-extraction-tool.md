# IaC Self-Service Extraction Tool

## Summary
A self-service toolchain that allows any team to scan their existing cloud
infrastructure using read-only credentials, extract it as Terraform HCL and state files, then
organise and customise their IaC. The goal is to make IaC adoption accessible to teams without
deep Terraform expertise, while ensuring clean, validated output that follows best practices.
The tool is actively being refined — not a one-off migration task but a reusable product that
needs to work reliably across different accounts, providers, and environments.

## Problem Statement
Teams have existing cloud infrastructure (AWS and Azure) not yet managed as IaC.
Manually writing Terraform for brownfield environments is slow and error-prone. This tool
automates extraction, handles provider-specific quirks, and produces output that teams can
immediately validate and use — without needing to understand the internals of Terraformer or
Terracognita.

## Stack
- **Primary extraction tools**: Terraformer (AWS), Terracognita (AWS + Azure)
- **IaC output**: Terraform HCL + `.tfstate` files
- **Scripting**: Bash
- **Cloud providers**: AWS (primary), Azure (secondary)
- **Auth**: AWS SSO profiles / exported temp credentials; Azure Service Principal (read-only)

## Architecture / How It Works

### AWS Extraction Flow
1. User provides read-only AWS credentials (SSO profile or exported temp credentials)
2. `1_terraform_import.sh` runs Terraformer to import AWS resources by type
   - Deletes resource files for non-existent resources automatically
3. `2_fix_providers.sh` fixes incorrect provider configurations generated by Terraformer
4. Post-extraction: drift check scripts reconcile generated HCL against actual cloud state
5. Iterative `terraform validate` + `terraform plan` cycle until zero-change plan achieved

### Azure Extraction Flow
1. User provides Azure Service Principal credentials (read-only, Reader role)
2. `terracognita-exclude-failures.sh` runs Terracognita iteratively:
   - Starts with a known exclusion list of unsupported/problematic resource types
   - On each run: detects new failures, parses the failing resource type, adds to exclusion list
   - Loops until a clean run is achieved
   - Outputs: `./generated-terracognita/*.tf` + `./terracognita.tfstate`
   - Also outputs `terracognita_final_excludes_copy_paste.txt` for reuse on future runs
3. `ARM_SKIP_PROVIDER_REGISTRATION=true` env var set to allow read-only SP to work without
   `*/register/action` permissions on the subscription
4. Post-extraction: same `terraform validate` + `terraform plan` clean-up cycle

### Common Post-Extraction Fixes Required
These are known issues with generated HCL that require scripted cleanup:

| Issue | Fix Applied |
|---|---|
| `vpc = true` deprecated on `aws_eip` (provider v5+) | `sed` removal |
| `source_code_hash` on Lambda without `filename` | Add `filename = "/dev/null"` + `lifecycle { ignore_changes }` |
| Computed attributes (`arn`, `hosted_zone_id`) hardcoded in S3 | `sed` removal |
| Base64-encoded `user_data` written as hex string | `sed` decode / `ignore_changes` |
| `cpu_threads_per_core` on bare-metal EC2 (invalid arg) | `sed` removal |
| Stale/orphaned resources (404 on extraction) | Added to exclusion list |
| Terracognita: unsupported resource types passed to `-e` flag | Pre-filter against valid type list |

### AWS Inventory Discovery Script
A comprehensive AWS CLI inventory script was built separately to:
- Scan the full AWS environment and list all resources across 25+ service categories
- Cross-reference against the Terraform AWS provider resource list
- Identify which resources are platform-managed (to exclude) vs. team-owned (to extract)
- Uses resource tags to distinguish platform-managed from team-managed resources
- Covers: VPC, EC2, S3, Lambda, RDS, ECS, EKS, API Gateway, CloudWatch, CloudTrail, Config,
  SecurityHub, WAF, SNS, SQS, DynamoDB, Cognito, SES, Kinesis, Glue, and more

## Key Technical Decisions

- **Terracognita for Azure over Terraformer**: Terracognita handles Azure Service Principal
  auth more reliably with read-only credentials; `--skip-provider-registration` equivalent
  via `ARM_SKIP_PROVIDER_REGISTRATION` env var avoids needing Contributor role
- **Iterative exclusion loop**: Rather than maintaining a static exclusion list, the script
  detects failures at runtime and builds the list dynamically — handles provider version
  differences and stale resources gracefully
- **Terracognita as discovery tool only**: Never enters CI/CD pipeline; used locally as a
  one-time or periodic extraction utility. Long-term IaC management uses native Terraform
- **Exported temp credentials over SSO profile for Terraformer**: Terraformer spawns its own
  Terraform provider process which doesn't reliably inherit SSO profile config; exporting
  `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN` from SSO is 100% reliable
- **Post-extraction drift check**: After extraction, a drift check script runs `terraform plan`
  across all generated modules to confirm zero-change — validates the IaC matches real state

## Known Limitations
- Terracognita (v0.8.4) supports a limited subset of Azure resource types — unsupported types
  must be excluded; full list hardcoded in script after running `terracognita azurerm resources`
- Terraformer-generated HCL often contains deprecated attributes requiring provider-version-
  specific cleanup scripts
- AWS SSO token expiry mid-run requires credential re-export; documented in runbook
- Shared AWS accounts may contain platform-managed resources that must be identified and
  excluded before extraction to avoid capturing infrastructure not owned by the team
- `terraform import` native blocks + `-generate-config-out` are the HashiCorp-native
  alternative but variable extraction is clunky — custom post-processing script built to
  parameterise hardcoded values into variables

## Reference Tools
- **Terraformer**: https://github.com/GoogleCloudPlatform/terraformer — reverse Terraform,
  reads existing cloud infra and generates HCL + tfstate. Broad AWS support (200+ resources).
- **Terracognita**: Open source, better Azure Service Principal support, iterative exclude
  pattern, outputs HCL + tfstate. Limited to azurerm v3.20.0 resource types.
